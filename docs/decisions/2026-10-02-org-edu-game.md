# ADR: 교육용 게임 개발을 위한 조직 개편 — 기획 결정 페어 · 개발 교차 검증 · 사용자 결정

- 상태: **Accepted**
- 일자: 2026-10-02
- 의사결정자: 사용자
- 작성: Claude Code 세션 (사용자와의 대화로 확정한 내용을 기록)

## 1. 맥락

- 목표가 백엔드 서비스 개발에서 **재미있고 교육적인 콘텐츠를 게임 앱으로 만드는 것**으로 바뀌었다. 연령·플랫폼은 범용(iOS·Android·태블릿·웹).
- 기존 7명은 백엔드 품질 게이트 중심이라 교육 근거·콘텐츠 설계·게임 설계·게임 클라이언트·아트/사운드 역량이 없었다.
- 사용자는 **결정권을 직접 갖고**, 서로 다른 모델(Claude·Codex)의 토론과 검증을 거친 선택지를 받기를 원했다.

## 2. 결정

1. **결정권자는 사용자 한 명.** 제임스는 결정하지 않는 진행자로 바꾼다 — 쟁점 정의, 토론 진행, 결정 요청서 상정, 결정 기록·인계, 상시 모니터링.
2. **기획 파트 — 결정 페어 3쌍** (같은 역할 파일, 다른 관점, Claude 1 + Codex 1)
   - 교육 리서치: 비고츠키(Claude) · 블룸(Codex)
   - 콘텐츠 기획: 파인만(Claude) · 세이건(Codex)
   - 게임 기획: 미야모토(Claude) · 라이트(Codex)
   - 진행: 독립 초안 → 교환 → 상호 비판 최대 2라운드 → 결정 요청서(Claude 작성, Codex 검토 서명) → 사용자 결정 (`roles/_team-workflow.md` §10)
3. **개발 파트 — 만드는 쪽 Claude, 검증하는 쪽 Codex**
   - 작성: 네이선(아키텍트), 마크(백엔드), **이와타(클라이언트, 신규)**, 수진(리서치), 수영(디자인 리드, 격상), **히사이시(아트·사운드 에셋, 신규)**
   - 검증: 정민(품질·보안), 카맥(성능) — Codex 로 전환, ADR 반론 담당 추가 (§11)
4. **기획 → 개발 인계 표** (§12)와 **Codex 사용 한도 확인 규칙** (§0.5.1)을 공통 워크플로에 둔다.
5. 히사이시는 외부 도구를 **매번 최신 웹 조사**(출처·확인일·상업/아동 이용 조건)로 제시하고 도입은 사용자가 결정한다.
6. 엔진은 미정. 후보 TypeScript 웹 + Capacitor(유력), Flutter + Flame, 콘텐츠에 따라 Unity. 기획 초안 후 수진 조사 → 네이선 ADR → 정민·카맥 반론 → 사용자 결정. 팀 도구는 엔진 중립으로 유지한다.

## 3. 검토한 대안

| 대안 | 내용 | 기각 사유 |
|---|---|---|
| A. 전원 페어 | 모든 역할을 Claude·Codex 로 이중화 (22 페인) | 비용·조율 부담이 과도함 |
| B. 결정 역할만 페어 (채택 기반) | 기획 3역할 페어 + 개발 교차 검증 | — |
| C. 엔진 분담만 | 역할마다 한 엔진, 다른 엔진이 검토 | 독립된 두 안이 나오지 않음 |

사용자는 B 를 바탕으로 개발 파트에 "Claude 작성 · Codex 검증" 구조를 더해 확정했다.

## 4. 결과

- 세션은 tmux 창 2개(기획 7명, 개발 8명)로 열린다. 구성 SSOT 는 `members.conf`, 개편 전 7명은 `teams/backend.conf`.
- 같은 역할 파일을 쓰는 페어가 서로를 알 수 있도록, 실행 시 멤버마다 **정체 블록**(이름·엔진·창·페어 상대)을 역할 지시 맨 앞에 붙인다.
- 역할 파일: 신규 5종(교육리서치·콘텐츠기획·게임기획·이와타·히사이시), 개정 7종(제임스 전면 개정, 네이선·마크·정민·카맥·수영·수진 조직 개편 절 추가), 공통 워크플로에 결정 권한·§10~12 추가.

## 5. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| Codex 5명이 계정 한도를 공유해 빨리 소진 (현재 Plus 플랜) | 기획 페어 effort medium 시작, `team-status --limits`, 30% 미만 시 사용자에게 선택지 보고 |
| 결정 요청이 사용자에게 몰려 결정 피로 | 제임스가 한 번에 3개 이하로 묶어 상정, 운영 판단은 자율 처리 |
| 페어가 서로 맞춰 가며 관점이 수렴 | 독립 초안 단계에서 상대 초안 열람 금지, 억지 합의 금지 |
| 기존 역할 파일의 Claude 전용 스킬 목록 | 공통 "실행 전 체크"에 Codex 대체 규칙, 정민·카맥 스킬 절에 대체 안내 |
| 페인 15개로 화면이 좁음 | 창 2개로 분리, `team-status` 로 전체 확인 |

## 6. 재평가 시점

- 첫 결정 페어 3건 진행 후 — 라운드 수·결정 요청서 품질·Codex 한도 소모를 보고 effort·라운드 제한을 조정한다.
- 엔진 결정 후 — 이와타·카맥·정민 역할 파일의 엔진별 기준을 구체화한다.
