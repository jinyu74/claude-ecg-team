# ADR: 내러티브 게임 팀 — 디렉터 위임 · 시나리오 결정 페어 · 프로젝트별 팀 분리

- 상태: **Accepted**
- 일자: 2026-10-02
- 의사결정자: 사용자
- 작성: Claude Code 세션 (사용자와의 대화로 확정한 내용을 기록)
- 선행: `2026-10-02-org-edu-game.md`

## 1. 맥락

- 사용자는 학습 게임과 별도로 **영화 같은 시나리오의 게임**을 만들고자 한다 — 플레이어가 주인공이 되는 몰입, 진행하며 곳곳에서 받는 감동, 엔딩의 가슴 먹먹한 여운.
- 기존 조직에는 시나리오 구조·인물·대본·연출 방향을 맡을 역할이 없었다. 세이건은 이야기 감각이 있지만 교육 콘텐츠에 묶여 있다.

## 2. 결정

1. **신규 멤버 3명**
   - 시나리오 기획 결정 페어: **닥터**(Claude, 인물·감정 중심) · **드럭만**(Codex, 구조·긴장 중심) — 공용 역할 파일 `roles/시나리오기획.md`
   - 디렉터: **우에다**(Claude Opus) — 톤 바이블·감정 지도·연출 방향·일관성 검수
2. **디렉터 위임** — 사용자가 **작은 창작 판단**(대사 문구 다듬기, 장면 안 연출 세부, 음악 큐 위치, 같은 의도 안의 표현 선택)을 우에다에게 위임한다. 모든 위임 판단은 `docs/direction/delegated-log.md` 에 기록하고 사용자는 언제든 뒤집을 수 있다. 줄거리·결말·인물의 운명·분기 구조·톤 바이블은 사용자 결정 (공통 §13).
3. **프로젝트별 팀 분리** — 학습 게임은 `members.conf`, 내러티브 게임은 `teams/narrative.conf`(14명, Codex 4명). 작업 폴더·tmux 세션도 분리한다.
4. **히사이시 음악 감독 확장** — 테마 선율 설계, 음악 큐 시트, 상황 반응 음악, 음성 톤 기준.
5. 공용 역할 파일을 두 프로젝트에서 쓰기 위해 팀 설정에 **`@project`** 지시어를 두고 정체 블록에 표시한다. 역할 파일의 유형별 항목은 해당 프로젝트에서만 적용한다. 게임 기획 역할은 프로젝트 중립으로 개정했다.

## 3. 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 학습 게임 팀에 3명 추가 (18명, Codex 6명) | 무관한 역할까지 한 세션에 떠서 비용·한도·화면 부담 |
| 디렉터 권한을 검수·권장으로만 한정 | 사용자가 작은 창작 판단 위임을 선택 — 결정 요청이 과도하게 쌓이는 것을 방지 |
| 시나리오 작가 1명 | 큰 창작 쟁점은 독립된 두 안의 비교가 필요해 페어 채택 |

## 4. 결과

- 신규 역할 파일 2종(시나리오기획·우에다), 개정: 게임기획(프로젝트 중립), 히사이시(음악 감독), 수영(시각 연출), 이와타(서사 시스템), 정민(내러티브 점검 항목), 제임스(디렉터 위임 처리), 공통 워크플로(프로젝트 유형, §13).
- `setup-team.sh`: 정체 블록에 프로젝트 표시, 합성 지시 파일을 **세션별 폴더**(`roles/.merged/<세션>/`)에 생성 — 두 팀을 동시에 띄워도 같은 이름 멤버의 파일이 섞이지 않는다.

## 5. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 위임 판단이 누적돼 사실상 큰 결정이 됨 | 누적 조짐 시 결정 요청서 전환 (우에다·제임스 양쪽 점검) |
| 두 팀 동시 운영 시 Codex 한도 공유 | `team-status --limits`, 한도 부족 시 사용자에게 선택지 보고 |
| 공용 역할 파일의 다른 프로젝트 항목 혼입 | `@project` 표시 + "해당 유형일 때만 적용" 규칙 |

## 6. 재평가 시점

- 첫 장(章) 대본 완성 후 — 위임 기록 양과 성격을 보고 위임 범위를 조정한다.
- 엔진 결정 후 — 대사·분기 도구(ink·Yarn Spinner 등)와 컷신 구현 방식을 이와타·네이선 역할에 반영한다.
